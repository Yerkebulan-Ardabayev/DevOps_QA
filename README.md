## Возможности

- Текстовый поиск (`/`) с ранжированием: совпадение в заголовке весит больше, чем в теле ответа
- Поиск понимает кириллическое написание латинских терминов («кубернетес» находит Kubernetes) и синонимы
- Голосовой поиск и активация по ключевому слову (Chrome/Edge, Web Speech API)
- Клавиатурная навигация: `/` — поиск, стрелки — переход между вопросами, `Backspace` — назад, `Escape` — на уровень выше
- Подсветка совпадений в результатах поиска — по тем же терминам, по которым сработало
  ранжирование, включая синонимы и транслитерацию (запрос «образ» подсветит `image`)
- Светлая и тёмная тема, переключатель в шапке. Выбор запоминается в `localStorage`,
  по умолчанию берётся системная; класс темы ставит инлайн-скрипт в `index.html`
  до первой отрисовки, поэтому при загрузке нет мигания чужим фоном

## Как устроен проект

Сайт — React + Vite (`DevOps_Interview/`), деплой на GitHub Pages через GitHub Actions.

Сами вопросы и ответы лежат не в коде, а в объекте `var DATA` внутри `DevOps_Interview.html`.
Этот файл лежит в двух местах и должен быть в них идентичным:

- `DevOps_Interview.html` — копия в корне репозитория;
- `DevOps_Interview/public/DevOps_Interview.html` — та, что раздаётся сайтом и загружается приложением.

При правке контента меняйте оба файла. Расхождение ловит тест `corpus.test.ts`.

## Разработка

```bash
cd DevOps_Interview
npm ci
npm run dev      # локальный сервер
npm run build    # production-сборка
npm run lint     # ESLint
npm test         # vitest: логика поиска + целостность корпуса
```

Тесты в `src/__tests__/corpus.test.ts` проверяют не только структуру данных (уникальные `id`
и номера, отсутствие заглушек, синхронность двух копий корпуса), но и типовые дефекты
конвертации и устаревшие технические детали. Если тест падает — он называет номера
вопросов, которые нужно поправить.
